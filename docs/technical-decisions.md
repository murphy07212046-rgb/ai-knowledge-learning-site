# 技术决策

## 独立站点实现

搜索结果：当前工作区没有可复用的 AI 学习站或知识更新服务；OrgStudio 前端与本项目无关，不复用其内部组件和依赖。

决策：使用原生 ES Modules、Node 内置测试与 Fetch API，不新增前端或服务端依赖。前端以静态文件部署，更新任务由 GitHub Actions 每日运行。

原因：产品面向公网，静态托管可降低运行成本和维护复杂度；Node 的内置能力已满足数据采集、分类、去重与测试需要。

## AI 产品实战内容

搜索结果：站点已具备数据驱动的学习模块、独立知识详情页、案例演练和原生 DOM 渲染，无需另行引入课程或表单框架。

决策：新增「AI 产品设计与交付」学习模块；在首页的每个学习模块下复用原生 `details` 提供默认收起的实战验收卡，包含任务、提交物、通过标准及可用的关联案例入口。

原因：将产品方法和技术知识放在同一学习路径中，同时保持首页信息密度可控。首期只定义可复用的交付与自评标准，不采集学习者的个人作业数据。
